# How to make an item

Every game or tool is one folder in `items/<slug>/`:

```
items/<slug>/
  index.html   the game/tool: HTML + CSS + JS in one file
  meta.json    titles and descriptions for the site
  thumb.png    generated by `npm run qa -- --thumbs` (do not draw by hand)
  hero.webp, intro.mp4 ...   optional media files (flat, no subfolders; see rule 2)
```

The site shows `index.html` inside an iframe on `/<lang>/<slug>/` and passes `?lang=ko` or `?lang=en`.

## meta.json

```json
{
  "slug": "same-as-folder-name",
  "date": "YYYY-MM-DD",
  "category": "silly | arcade | puzzle | chill | random | tools",
  "kind": "game | tool",
  "aspect": "9/16",
  "ko": { "title": "...", "desc": "한두 문장 소개 (40~120자)", "howto": "조작법과 목표", "about": "선택: 만든 이야기나 팁" },
  "en": { "title": "...", "desc": "One or two sentences (40-160 chars)", "howto": "Controls and goal", "about": "optional" }
}
```

`aspect` is the shape the item looks best in: `9/16` (phone-style, preferred for games), `1/1`, `4/3`, `16/9`, or `3/4` for tools.
Titles: short, catchy, searchable. A tool's Korean title should contain the words people actually search for (e.g. "사다리타기", "N빵 계산기").

## Hard rules for index.html

1. **Original work only.** Genre mechanics are fine (stacking, dodging, matching, ladders...). Never copy the name, characters, art, music, levels or look of an existing game, and never use trademarks or real people.
2. **Self-contained, no network.** No external scripts, fonts, CDNs, `fetch`, `XMLHttpRequest`, `WebSocket`, analytics, and no `http(s)://` URL for any asset. Everything the item needs ships in its own folder.
   - **Games (`"kind": "game"`) draw with SVG, canvas, CSS or emoji.** No raster images or video, because game art must stay sharp at every size and load instantly. `.svg` files in the folder and inline SVG are fine.
   - **Information and humor items (`"kind": "tool"`) may use images and video**, including ones generated with Gemini. Put them in the item folder and reference them by a relative path (`./hero.webp`, `./intro.mp4`), or inline them as data URIs. Allowed types: `png`, `jpg`, `webp`, `gif`, `svg`, `mp4`, `webm`. Keep files flat: the build copies only top-level files, not subfolders.
   - **No size limit is enforced.** Big files load slowly on phones, so compress where it costs nothing visible (webp for images, H.264 mp4 or webm for video). Know the platform ceilings, because they fail a deploy or a push rather than a test: Cloudflare Pages rejects files over 25 MiB, and GitHub blocks files over 100 MB (both from general knowledge, not checked against the current docs). Large binaries also stay in git history forever.
   - **Video:** autoplay only when `muted` and `playsinline`; never autoplay sound (rule 8). Pause it when `document.hidden`, respect `prefers-reduced-motion`, and keep clips short and looped only when they are decoration.
   - Generated media still follows rule 1: original work, no real people, no trademarks, no look-alikes of existing characters.
3. **Fills its window.** The iframe can be any size from 320×480 up to fullscreen desktop. Use `100vw/100vh` (or `100dvh`), recompute layout on `resize`, never scroll the page, and keep everything readable at 320 px wide.
4. **Works with touch, mouse and keyboard.** Use pointer events. Big tap targets (44 px+). Call `preventDefault` on game keys and touches so the page does not scroll or zoom (`touch-action: none` on the play area).
5. **Both languages.** Read `new URLSearchParams(location.search).get('lang')` (fallback: `navigator.language`), and keep every visible string in a `{ ko: {...}, en: {...} }` dictionary. `<html lang>` must match.
6. **Game loop for games:** a start screen (title, one-line how-to, "tap to start"), play, a game-over screen with score, best score and a big retry button. Restart must fully reset state.
7. **Best score / settings** in `localStorage`, always inside `try/catch` (storage can be blocked).
8. **Sound is optional.** If used, synthesize it with Web Audio after the first user gesture, and provide a mute toggle. Never autoplay.
9. **Be kind.** Silly humor is welcome (office life, Korean daily life, cats, food); nothing hateful, sexual, gory, political or mocking real groups.
10. **Performance.** `requestAnimationFrame`, frame-rate independent movement (use delta time, capped), pause when `document.hidden`, handle high-DPI canvas (`devicePixelRatio`, capped at 2).
11. **No dialogs.** No `alert`, `confirm`, `prompt`, `window.open`, or navigation away from the page.
12. **Visual quality matters.** A clear color palette, readable type (system-ui font stack), simple juicy feedback (shake, pop, particles, flashes) and a satisfying game-over screen. It should look finished in a screenshot.

## Before publishing

```bash
npm test             # validates meta.json and the hard rules it can check statically
npm run build        # builds dist/
npm run qa -- --thumbs   # plays every item headlessly, fails on JS errors, writes thumb.png
```

Fix every error QA reports. Check the generated thumb looks like a real screenshot of the game, not a blank screen.
