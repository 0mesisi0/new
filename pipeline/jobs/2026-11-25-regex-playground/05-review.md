# Review 2026-11-25-regex-playground

## Blocking

1. **The results panel is clipped in short mobile iframes.** The stacked layout requires at least 478 px of height, while a 320 px-wide, 3:4 iframe is about 427 px tall and the site can render it shorter still. With page overflow hidden, the bottom of the panel falls outside the viewport, where its internal scrollbar cannot bring it into view. Let the stacked sections shrink at short heights while preserving the 44 px controls. This was verified from the CSS. Live browser verification was blocked by the environment. [Item layout](C:/work/haruhanpan/play/items/regex-playground/index.html:24), [iframe layout](C:/work/haruhanpan/play/src/style.css:56)
2. **Worker fallback can leave the page unresponsive and misreports the slow demo.** The fallback runs user patterns synchronously, and its 3,000-character cap and heuristic cannot bound execution time. The heuristic also rejects the spec’s shortened slow preset before running it, then displays a message claiming execution was stopped after 0.4 seconds. Preserve isolation when testing arbitrary patterns and use a distinct message when execution is skipped. [Fallback and timeout](C:/work/haruhanpan/play/items/regex-playground/index.html:355)
3. **The match engine can lose a valid named capture, and the explanation misreads Korean group names.** `(?<__proto__>a)` loses its named entry when the result is copied into a plain object. `(?<이름>a)` matches successfully, but Explain describes it as an unnamed group followed by literals. Preserve the engine’s named-capture keys and recognize the group names ECMAScript accepts. [Capture packing](C:/work/haruhanpan/play/items/regex-playground/index.html:273), [group tokenizer](C:/work/haruhanpan/play/items/regex-playground/index.html:590)
4. **Highlights and match rows can refer to the wrong text during edits.** Inserting characters before an existing match immediately paints the old match offsets onto the edited text. Activating an old row can select those same obsolete offsets while the new job is pending. Clear or disable stale results on text changes, and only retain dimmed highlights for an invalid pattern when they belong to the current text. [Highlight rendering](C:/work/haruhanpan/play/items/regex-playground/index.html:439), [match selection](C:/work/haruhanpan/play/items/regex-playground/index.html:522), [text input handler](C:/work/haruhanpan/play/items/regex-playground/index.html:709)
5. **Unfocused input boundaries have insufficient contrast.** The `#e3dfd6` border is about 1.33:1 against white. The pattern and replacement inputs rely on that border to show their bounds. Give those boundaries at least 3:1 contrast against adjacent colors. [Pattern input](C:/work/haruhanpan/play/items/regex-playground/index.html:36), [replacement input](C:/work/haruhanpan/play/items/regex-playground/index.html:100)
